# headless_frotz

A spec-complete, pipe-drivable Z-machine interpreter (`dfrotz`) built and
working on this Windows machine, complementing the home-grown `ztest.py`
interpreter in the repo root.

## Status: working

`dfrotz.exe` (Frotz 2.55 dumb interface, built with TinyCC) runs v3 and v5
story files from a pipe with clean plain-text output. Verified against:

- `hitchhiker-r59-s851108.z3` (Infocom v3) — loads, plays, quits cleanly
- `../test_lovecraft.z5` (v5) — loads, plays, score works

Usage:

    dfrotz.exe -m -q STORYFILE          # -m: no MORE prompts, -q: quiet
    echo look | dfrotz.exe -m -q game.z3

Useful options: `-m` (turn off MORE prompts — essential for scripted play),
`-q` (quiet), `-p` (plain ASCII), `-s #` (random seed), `-h #`/`-w #`
(screen size), `-L <file>` (load save), `-R <path>` (restrict file access).

## Why

- The only local Frotz was `../frotz/Frotz.exe`, a GUI app that cannot be
  driven from a pipe. This is the documented reason `ztest.py` exists.
- `ztest.py` is a from-scratch Z-machine **v5-only** interpreter, married
  to the local Inform 6.44 build (it relies on that compiler's
  non-standard routine headers, which omit local initial-value words).
  It cannot run spec-conformant story files, including v3 games.
- dfrotz is spec-complete across v3–v8 and battle-tested.

## How dfrotz.exe was built

No C compiler existed on this system (no gcc, clang, MSVC), so the build
uses **TinyCC 0.9.27** (a ~500 KB portable C compiler) against the Frotz
2.55 source from the if-archive. Everything lives in `build/`:

    build/tcc/tcc/tcc.exe          TinyCC compiler
    build/frotz-2.55/              Frotz 2.55 source + dfrotz.exe output
    build/frotz-2.55/compat/       shim headers added for tcc/Windows

Rebuild command (from `build/frotz-2.55/`):

    ../tcc/tcc/tcc.exe -Icompat -Isrc/common -Isrc/dumb -Isrc/blorb \
        -o dfrotz.exe src/common/*.c src/dumb/*.c src/blorb/*.c

Three source adjustments were needed (all in `build/frotz-2.55/`):

1. `src/common/defs.h` and `src/common/hash.h` are generated by the
   Makefile at build time but absent from the release tarball; they were
   written by hand (buffer sizes, `VERSION`, `GIT_HASH`, plus
   `NO_BASENAME` and `NO_STRNDUP` to route around missing POSIX
   functions via `missing.c`).
2. `compat/sys/param.h` — minimal shim (MIN/MAX macros); tcc lacks it.
3. `compat/unistd.h` — shim mapping to `<io.h>`/`<process.h>`.

Remaining tcc warnings (`PATH_MAX redefined`, an implicit `strrchr`
declaration in `missing.c`) are harmless.

## Dead end: WinFrotz console build + pseudo-console (kept for reference)

Before building dfrotz, the attempted approach was driving the prebuilt
Win32 Console Frotz 2.32 (`WinFrotzConsole/WinFrotz.exe`, from the
if-archive) through a pseudo-console (`wfrotz.py`: pywinpty + pyte
terminal emulation). It works for short v5 sessions but was abandoned:

- WinFrotz queries the console size at startup and dies under a bare
  pty unless given explicit `-h/-w` switches.
- `\r\n` input arrives as two Enters; only `\r` works.
- On long runs WinFrotz repaints its virtual screen constantly (~3.5 MB
  of redraw traffic for ~50 KB of game text) and the pyte model drifts.
- For the v3 target the conpty translation lost the game text entirely:
  WinFrotz writes text at the bottom row and the console repaint clears
  it, so the rendered screen showed only the status line and prompt.

`wfrotz.py` is kept as a record of that approach; `dfrotz.exe` needs none
of it (it reads stdin and writes plain text natively).

## Files

- `dfrotz.exe` — the working interpreter (Frotz 2.55 dumb interface)
- `build/` — TinyCC, Frotz source, shims, rebuild recipe above
- `wfrotz.py` — the abandoned pty wrapper (reference only)
- `WinFrotzConsole/` — prebuilt WinFrotz 1.08 (Frotz 2.32 console);
  download from
  https://www.ifarchive.org/if-archive/infocom/interpreters/frotz/WinFrotzConsole108.zip
- `hitchhiker-r59-s851108.z3` — local test file, not committed
  (copyrighted Infocom material)

## Relationship to the repo's testing tooling

- `ztest.py` remains the regression harness for the v5 game (its
  `--mark`/scripted workflow and the gym server depend on it).
- `dfrotz.exe` is the tool for spec-conformant story files, v3 games,
  and any future cross-checking of `ztest.py` behaviour against a
  reference interpreter.
